# Handoff — Story Image Generation

**Goal:** Generate companion-character artwork for Story Mode. For every **scene**,
three images of that scene's companion: **neutral**, **happy**, **a bit angry**.
Posture and background vary per scene.

Two delivery paths, same method:
- **Part A — Premade stories:** batch-generated ahead of time.
- **Part B — Custom stories:** generated at runtime, alongside story generation.

> Feasibility is confirmed: the project's Gemini API key successfully generates
> images with `gemini-2.5-flash-image`. This doc is the spec to implement it.

shape with whoever does the multi-scene work *before* you start.

## 2. Image spec

- Per scene: **3 images** — `neutral`, `happy`, `angry` (a bit angry, mild).
- Within a scene's 3 images: **same character, outfit, pose, background — only
  the expression changes.**
- Across scenes of one story: same character, **different background + posture**.
- Across stories: different companions.
- Style: match the existing anime illustrations in
  `flutter_app/assets/images/`.

---

## 3. Generation method (Gemini)

- **Model:** `gemini-2.5-flash-image` ("Nano Banana") — confirmed working.
  Also available and worth A/B testing: `gemini-3.1-flash-image-preview`.
- **API key:** `GEMINI_API_KEY` in `backend/.env` (also in Cloud Run Secret
  Manager as secret `gemini-api-key`). Do not hardcode it.
- **Library:** `google-genai` (already in `backend/requirements.txt`).

### Consistency technique — the critical part

Do **not** generate the 3 expressions independently — they will drift (different
hair, pose, background) and look like a flicker. Instead:

1. Generate or obtain the **neutral** image first — this is the **anchor**.
2. Generate `happy` and `angry` by **image-editing the neutral anchor**: pass the
   neutral image *as input* and instruct "same person, same everything, change
   only the expression". Nano Banana preserves identity when editing.
3. Same trick for a new scene: pass the character's anchor + "keep this exact
   person and outfit, new background + pose".

### Reference snippet

```python
from google import genai
from google.genai import types

client = genai.Client(api_key=GEMINI_API_KEY)

def first_image_bytes(resp) -> bytes:
    for cand in resp.candidates or []:
        for part in cand.content.parts or []:
            if getattr(part, "inline_data", None) and part.inline_data.data:
                return part.inline_data.data
    raise RuntimeError("no image in response")

# 1. neutral anchor — text-to-image (or load an existing asset's bytes)
resp = client.models.generate_content(
    model="gemini-2.5-flash-image", contents=NEUTRAL_PROMPT)
neutral_png = first_image_bytes(resp)

# 2. happy / angry — EDIT the neutral image so identity is preserved
resp = client.models.generate_content(
    model="gemini-2.5-flash-image",
    contents=[
        types.Part.from_bytes(data=neutral_png, mime_type="image/png"),
        HAPPY_EDIT_PROMPT,
    ],
)
happy_png = first_image_bytes(resp)
```

## 4. Prompt templates

**Neutral (text-to-image, when generating a fresh character):**
> Anime-style illustration, full body, portrait orientation, of {companion
> description from the premise}. Calm, friendly, neutral expression. Setting:
> {scene setting}. Natural standing pose. Soft natural lighting, warm colours,
> clean modern anime art style. The character is the clear focal point.

**Happy (edit of the neutral anchor):**
> Using the provided image: keep the exact same person, outfit, hairstyle, pose
> and background. Change ONLY the facial expression to a bright, warm, happy
> smile with cheerful eyes.

**Angry (edit of the neutral anchor):**
> Using the provided image: keep the exact same person, outfit, hairstyle, pose
> and background. Change ONLY the facial expression to slightly annoyed / a bit
> angry — lightly furrowed brows, a small frown. Keep it mild, not aggressive.

**New scene (edit of an anchor, when reusing a character):**
> Using the provided image: keep this exact same person, outfit and hairstyle.
> Place them in a new setting: {new scene setting}. New natural pose suited to
> the setting. Same art style.

Each premade story's premise already names and describes its companion (e.g.
*"a warm, cheerful local woman named Akari"*) and gives the setting — build the
prompts from `premise` + `title`.

## 5. Part A — Premade stories (batch)

Write a standalone script: `backend/scripts/gen_story_images.py`.

For each of the 20 `PREMADE_STORIES`:
1. Resolve the companion (name + description live in the `premise` text).
2. Establish the neutral anchor — **reuse an existing asset if one fits this
   persona** (§7), else generate it.
3. Generate the 3 expression images for the (currently single) scene.

Output → `flutter_app/assets/images/story/<story_slug>/<scene_idx>/{neutral,happy,angry}.png`
(`assets/images/` is already registered in `pubspec.yaml`). Run once, commit the
images.

## 6. Part B — Custom stories (runtime)

Hook in **`create_node_story()`** (`node_stories.py:131`), right after
`generate_story_nodes()` succeeds. (Optionally also the lazy path in
`get_node_story()`, `node_stories.py:105`.)

- **Storage:** runtime images **cannot** go in `assets/` (bundled at build
  time). Upload to **Supabase Storage** — a public bucket, e.g. `story-images/` —
  and store the returned public URLs. Supabase is already the project's DB, so
  this is the path of least resistance.
- **Latency:** generation is several seconds × 3 images × scenes. Recommended:
  return the created story immediately, generate images in a **background task**,
  and let the app refresh/poll. Blocking the create call also works but feels
  slow.

## 9. Rate limits & cost

The Gemini key is **free-tier** — image generation has a low daily quota.
20 premade stories × 3 images (× future scenes) will likely exceed one day's
quota. Mitigate by: throttling + batching across days, reusing existing assets,
or enabling billing on the Gemini project. Runtime custom-story generation also
draws on the same quota — monitor it.
